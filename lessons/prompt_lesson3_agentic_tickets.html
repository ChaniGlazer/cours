עקרון 3

Refactor ובנייה חדשה הן שתי שפות שונות

באותו כלי, שתי משימות שונות לגמרי דורשות ניסוח שונה לגמרי. לחצו כדי לעבור בין המצבים:

האילוץ המרכזי: שימור התנהגות

  • scope מוגדר: "only in src/payments/"
  • טסטים קיימים חייבים לעבור, בלי שינוי
  • שלבים קטנים + טסט אחרי כל שלב
  • אסור לשנות API ציבורי (אם רלוונטי)

It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality.

⚠️

היזהרו מ-over-engineering: סוכנים נוטים להוסיף הפשטות לא נדרשות באמצע refactor. אם לא ביקשתם — ציינו שלא רוצים שכבות הפשטה חדשות.

האילוץ המרכזי: לא להיות מינימליסטי מדי

הסוכן נוטה לבנות את המינימום שעונה על הבקשה המדויקת:

build the settings page… be ambitious: empty and error states, the save flow wired up, keyboard navigation

  • "be ambitious" — לא רק מה שהתבקש במפורש
  • "follow the pattern in X" — תבנית קיימת לחיקוי
  • לחשוב מראש על מצבי קצה: ריק, שגיאה, טעינה
